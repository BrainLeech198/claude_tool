# Claude 启动器

Windows 上的 Claude Code 图形启动器：左边一列工作区，右边看选中的这一本、
按一下开会话。单文件起家，现在拆成了一个包，目标是可以打包成
安装程序转发给别人。

## 现在能干什么

- **模型切换**：预设存成一个个 json，点一下覆盖 `~/.claude/settings.json`。
  内置国内四家 + 国外六家的 endpoint 和模型名，选一家贴个 key 就能用。
  带"测试"按钮——真打一次请求看通不通，连不上会把底层原因（超时/DNS/拒绝）
  一起显示出来。
- **工作区列表**：左边一列就是工作区，点一下**选中**它（不再直接开窗口），
  右栏显示这一本的名字、路径、本机 claude 版本和当前模型。开会话按右栏那颗
  「新会话」/「接着上次」；改名、搬迁、上下挪、移除、删交接文档都在右栏的
  「管理」那排。行首那个编号就是 Ctrl+数字按的那个号（顺序也按它）。
  右栏在目录里真有交接文档时会多出一颗「删交接文档」，丢进回收站而不是永久删。
- **agent 档位**：每个工作区自己挑用哪个 agent（Claude Code 或 CodeBuddy），
  右栏随时切换。切了之后开会话、查版本、装/升级都跟着走——CodeBuddy 那边没有
  一键装法，要装得去它自己官网。
- **共享记忆**：项目根的 `AGENTS.md` 是两个工具都读都写的那份记忆。开新会话时
  自动注入一段系统提示，告诉 AI 先读它、写记忆也写进它（而不是各自工具的
  专属记忆文件）。有 `AGENTS.md` 才注入，没有就不打扰。
- **权限等级**：每次启动前自己选（每次都问 / 改文件不问 / 只规划 / 让模型批 /
  什么都不问），选过的按工作区记住。下拉里同时给出中文解释和 `acceptEdits`
  这类真名。
- **交接文档**：从这个启动器开出去的窗口，顶上"正在跑"那块会列出来，每条带
  一个"整理交接文档"——在那个目录里 fork 一份会话，让它把当前工作状态写成
  `handoff.md`。只在你点的时候写，不自动刷。
- **独立窗口的控制**：在"正在跑"那行直接对那扇终端窗口动手——挪到启动器旁边、
  压到最上层、关掉。认的是窗口句柄（启动前后比对窗口名单拿到），所以窗口是
  用户的 Windows Terminal，照样能控制。
- **换模型时接着聊**：切换模型后，正在跑的会话逐个问"要不要接着聊"；答应的话
  关掉旧窗口、用新模型 `--continue` 重开（接着聊靠 claude 自己的 `--continue`，
  这条路不写交接文档），全程在主界面上有一块带进度条和已用秒数的区域。
- **自动继续**（可选，默认关）：挂在会话的 Stop hook 和 PreToolUse hook 上，它停下来
  问话、或者摆选项框问你时，都替它接一句"接着干，自己定"，连着推几轮；它自己说
  "已完成"就停。
- **AI 托管**（分三档，默认不选）：在工作区标题底下「AI 托管」里挑一档、写一段任务目标，
  起一个新会话让它自己往下做。第 1 档让它自己定；第 2 档从你的预设里挑一个模型当副手，
  读会话记录替你拍板（答不上来退回第 1 档）；第 3 档平时自己跑，碰上改 git 历史、删东西
  这类动作停下来等你点头。
- **没装 claude 时帮着装，旧了也帮着升**：找不到 claude 就在顶上挂一条横幅，点
  「帮我装 claude」开一个面板——先列这台机器上是什么（系统、有没有 winget / brew /
  npm、Node 是哪个版本），再把能走的装法一条条摆出来（官方原生脚本排第一：不依赖
  Node、装完自己管更新；下面才是 winget / Homebrew / npm），前提不满足的那条灰着
  并写明差什么。连 Node 都没有的那台机器上，最后那条「便携版 Node + npm」把官方
  那个 Node 便携包整个下到启动器自己的目录（`~/.claude_tool/node`），再拿它自带的
  npm 装 claude——不用你先自己去折腾一个 Node。这条只写 `~/.claude_tool/` 里面，
  不动系统 PATH、不碰注册表，卸载就是把那个目录删掉。挑一条就显示要跑的命令
  （能复制），点一下先问一句，然后过程直接流在面板里，装完自己再找一遍 claude。
- **内嵌终端**：可选，把 conhost 塞进主窗口，不用另开窗口。默认关。
- **claude 版本**：右栏详情里写着本机 claude 是哪个版本，旁边「查更新」问一次网上出到
  哪版了；本机落后就在**顶栏**冒一颗「有新版」，点开的是同一个面板的**升级模式**：
  它先看这份 claude 当初是哪条路装的（只看它落在哪个目录，不翻注册表也不去问包
  管理器——那要花好几秒），把那条对的升级命令填好并预选上（winget 装的给
  `winget upgrade`、brew 装的给 `brew upgrade`；官方脚本和 npm 那两条本来就是
  "再跑一遍就是升级"，命令不用换），其余每条都写明"不是这条装的，选它会再装一份"。
  认不出来就不替你选，退回第一条能走的。启动时自动查要单独打勾（会联网，默认关）；
  从「有新版」升成功之后，下一次起来时会强制再查一次，好让那颗胶囊掉下去。
  官网每一条版本记录里也会写明"配 claude 哪个版本测过"。
- **启动器自己的新版**：每次启动都自动问一次官网（查的是我们自己那份 releases.js，
  量很小，不用打勾），查出网上的比本机新，顶栏就冒一颗「下载最新版 X」——点一下就把
  安装包下到 `~/.claude_tool/downloads/`，下完问一句要不要现在装（装它得先关掉启动器，
  安装程序要覆写的正是这些文件）。别的系统上产物是 tar.gz，没有安装器，就只弹出它所在
  的那个文件夹。这条跟上面 claude 那条是两回事：claude 那条联网默认关、要自己打勾。

## 跑起来

从源码跑（开发用，看得见报错）：

```bat
运行.bat
```

需要 Python 3（只用标准库，零第三方依赖）。

打完包之后给别人的是安装包，那边**不需要装 Python**：

```bat
build\打包.bat
```

出 `Output\ClaudeLauncher-<版本>-Setup.exe`。装的时候默认免管理员、装在自己账户
下；同一个目录也可以直接拷走双击运行，那份是免安装的。

## 目录

```
claude_tool/       源码包，见 设计说明.md 里的模块划分和依赖方向
设计说明.md        设计说明
build/             PyInstaller spec、Inno 脚本、图标、打包用的 bat
docs/              官网，GitHub Pages 就发这个目录，下载直链指 Gitee 发行版
```

官网发的是 `docs/` 这个目录的原因：GitHub Pages 的「Deploy from a branch」只认仓库
根 `/` 或 `/docs`，中间没有别的选项。发布源设成 `master` 分支 + `/docs` 目录即可，
不需要任何 Actions 或额外的 token 权限。

发一版要手动做的只有两件：把 `claude_tool\__init__.py` 里的 `__version__` 改掉；在
Gitee 和 GitHub 上**各**建一个 tag 为 `<版本号>`（`0.1.0` 这样，不带 v）的发行版，
把 `Output\` 里那个 Setup.exe 传成附件。GitHub 那份就是官网卡片上「GitHub 下载」
那个入口指的地方——仓库代码是镜像过去的，**发行版附件不跟着镜像走**，得自己传。
其余都包在 `build\打包.bat` 里了，包括把这一版记进官网的版本清单（顺带读一次
打包机上的 `claude --version`，写进"这版配着哪个 claude 测过"那一格）。

用户数据在 `~/.claude_tool/`，跟 Claude Code 的配置分开，卸载时不该删。
详见 [设计说明.md](设计说明.md)。
