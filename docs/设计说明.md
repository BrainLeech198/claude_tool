# 设计说明

这个启动器是干什么的、代码怎么切、为什么这么切。改代码之前先看这份。

## 它解决什么问题

Claude Code 原生的用法是 `cd 到项目目录，敲 claude`。两个麻烦：

1. **换模型要手改 `~/.claude/settings.json`。** 国内几个模型的 endpoint 和
   模型名各不相同，每次改都得翻文档、抄地址、贴 key。
2. **工作区散在硬盘各处。** 每个项目都要 `cd` 过去，记不住路径。

所以它做了两件事：把模型预设存成一个个 json，点一下就覆盖
`~/.claude/settings.json`；把工作区存成一个列表，点一下就在那个目录开窗口
跑 claude。两块互不干扰，启动前随时换模型。

## 数据放在哪

**启动器自己的东西全在 `~/.claude_tool/` 下面**，跟 Claude Code 的配置分开：

| 路径 | 装什么 |
| --- | --- |
| `launcher.json` | 工作区列表、窗口位置、默认工作区目录 |
| `claude_settings/*.json` | 模型预设，一个模型一个 json |
| `workplace/` | 默认工作区目录，"＋ 新建文件夹"就在这儿建 |
| `hooks/auto_handoff.json` | 自动刷交接文档用的那段 Stop hook 配置 |
| `handoff_state.json` | 自动刷文档的节流计数，按目录分开记 |

**唯一的例外是 `~/.claude/settings.json`**——那是 Claude Code 自己的文件，
换模型是往里覆盖一份新内容。除此之外不碰 Claude Code 的任何东西。

这一点直接决定了安装包的行为：**卸载时不能删 `~/.claude_tool/`**，那里面
是用户全部的预设（含 API key）和工作区列表。卸载程序只留一句提示。

## 代码怎么切

```
claude_tool/               包
├─ __main__.py             入口：--handoff-hook 走 hook，否则开窗口
├─ paths.py                所有目录/文件/命名规则常量
├─ theme.py                配色、字体、量文字宽度
├─ permissions.py          权限等级表
├─ config.py               launcher.json 读写、工作区扫描、上次聊时间
├─ presets.py              模型预设 + 常用供应商表
├─ claude.py               找 claude、拼命令行、启动
├─ handoff.py              交接文档 + Stop hook 本体
├─ winhost.py              ctypes 的窗口操作、内嵌 conhost 终端
├─ widgets.py              自绘控件：胶囊按钮、列表行、滚动区、表单工具
└─ ui/
    ├─ launcher.py         主窗口
    └─ dialogs.py          那几个对话框
```

`ui/launcher.py` 1039 行，`ui/dialogs.py` 482 行。

### 对话框为什么是 mixin

`dialogs.py` 里的 `LauncherDialogs` 是个 mixin，`class Launcher(LauncherDialogs,
tk.Tk)` 继承它。**方法体一行没改**——它们本来就全是 `self.xxx`，跟主窗口共用
`config_data`、`feedback_var`、`refresh_*` 这些状态。

没做成"把状态收进一个独立的对象再注入"，是因为那要挨个改方法体（每个
`self.config_data` 都得改成 `panel.config_data`），跟"只是把文件切开"是两码事，
风险也不在一个量级。真要那么做，应该连同 `launcher.py` 一起，按面板
（模型面板 / 工作区面板 / 会话面板）重新划分职责，而不是先动对话框。

留在 `launcher.py` 的是**面板自己会调**的那些：`remove_model`、`switch_model`、
`launch_workspace`、`rescan`，以及 `_set_workplace`——它跟
`_build_workplace_note` / `_refresh_workplace_note` 是一整套，拆开反而碎。

依赖是单向的，从下往上：

```
paths / permissions / theme        谁都不依赖
        ↓
      claude  ← handoff / winhost / presets
        ↓
      config        （依赖 paths + permissions）
        ↓
     widgets        （依赖 theme）
        ↓
        ui          （依赖所有）
```

**只有 `ui/` 会 import tkinter。** 这不是洁癖，是硬要求：`--handoff-hook`
那条路上不能碰 tkinter，也不能弹任何窗口——那是 Claude Code 在跑对话的
中途回头调的。所以 `__main__.py` 把 hook 分支单独拎出来，连主界面都不 import
（在 `main()` 里面才 import），保证这条路干干净净。

同理，`claude_tool/__init__.py` 是空的。它一旦往里放 import，上面那条
隔离就白做了。

## 两个必须知道的坑

### hook 命令行指向哪儿

`handoff.py` 里 `ensure_handoff_hook_settings()` 要写一条命令行给 Claude Code，
让它每次停下来回头调我们。源码模式下它是：

```
"python.exe" "…\claude_tool\claude_tool\__main__.py" --handoff-hook
```

**不能写 `handoff.py` 自己。** 那样会被当成脚本直接跑，包内的
`from claude_tool.xxx import` 全部失败。同理 `__main__.py` 里有一段
`sys.path` 引导，就是为了让它既能被 `python __main__.py` 直接跑，也能被
`python -m claude_tool` 跑。

打包成 exe 之后这条命令要变成 `<exe> --handoff-hook`，靠
`getattr(sys, "frozen", False)` 分叉——这一步在打包时做，现在还没加。

### 标准输入输出的编码

这台机器 locale 是 cp936。Python 走管道时 `sys.stdin` / `sys.stdout` 默认按
GBK 编解码，而 Claude Code 给的是 UTF-8。只要路径里有中文（工作区叫「冉」
「小说」这种），`json.load(sys.stdin)` 就抛 `UnicodeDecodeError`，被 except
吞掉，表现为"这个功能对中文工作区永远不触发"，且没有任何报错。

所以 hook 里是 `sys.stdin.buffer.read().decode("utf-8", "replace")`。**任何
新加的、跟外部进程走标准输入输出传数据的地方，都要显式按字节 + UTF-8 处理。**

## 怎么跑

```bat
运行.bat
```

等价于 `python claude_tool\__main__.py`。这条路上看得见报错，开发时用。
打包出来之后，给用户的是开始菜单里的快捷方式，不依赖机器上有没有 Python。

单独试 hook：

```bat
echo {"cwd":"D:\\某目录"} | python claude_tool\__main__.py --handoff-hook
```

什么都不打印 = 放行；`{"decision":"block",...}` = 把 claude 拦下来再干一轮。

## 还差什么

- **打包。** PyInstaller（onedir，不要 onefile）→ Inno Setup。onedir 启动快、
  杀软误报少，反正 Inno 装的就是一个目录。要处理的：
  - `--noconsole` 的 exe 里 `sys.stdout` / `sys.stdin` 是 `None`，
    hook 那套 stdio 要走原始文件描述符 0/1 重写一遍。
  - hook 命令行换成分叉后的 exe 路径，注意 `Program Files` 里的空格要带引号。
  - 卸载程序**不要**删 `~/.claude_tool/`。

## 搬运式重构怎么保证没改坏

拆模块和拆对话框都是纯搬运，但"搬运时少抄一行 import"这类错误，在运行到
那条分支之前不会暴露。这两次用的三道检查，以后大改结构可以照做：

1. **定义集合与源码文本比对。** 用 `ast` 取出重构前的每个函数，跟重构后的
   逐字比。结果应该是"除了有意改的那几处，其余全等"。
   注意**别把类整体算进去**——`Launcher` 换了基类、去掉一半方法，类那段文本
   本来就该变，算进来只会报一条没意义的"文本变了"。
2. **漏 import 扫描。** 反汇编每个模块，把所有 `LOAD_GLOBAL` 的名字揪出来，
   既不在本模块 globals 里、又不是内置的，就是漏了 import。注意要按
   `__module__` 过滤，否则一路 import 进来的函数会按本模块的 globals 去量，
   满屏假报错。
3. **多余 import 扫描。** 反过来说，搬走之后原模块会剩下一堆没用的 import。
   数一下每个 import 进来的名字在文件里出现的次数，只出现一次（就是 import
   那一行）的列出来手工核。这个只能当提示，字符串和注释会造成误判。

外加 A/B 截图：同一套沙箱配置下，重构前后各跑一遍，截屏逐像素比。主窗口和
"加模型"对话框都这么比过。两个坑：
- **要排除窗口阴影那一圈**——它是 DWM 拿桌面背景混合出来的，跟代码无关，
  不排除的话满屏都是 1-2 个像素的假差异。
- **沙箱路径要写死**，别用 `mkdtemp`：临时目录名每次都变，界面上那行路径
  跟着变，逐像素比时全是噪声。

还有一件容易漏的：界面上跑不到的分支（错误提示、异常处理）三道检查都盖不住
——它们只保证"搬运没错"，不保证"逻辑对"。真遇到这类分支，单独写探针去撞它。
