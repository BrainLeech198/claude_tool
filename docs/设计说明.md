# 设计说明

这个启动器是干什么的、代码怎么切、为什么这么切。改代码之前先看这份。

## 它解决什么问题

Claude Code 原生的用法是 `cd 到项目目录，敲 claude`。两个麻烦：

1. **换模型要手改 `~/.claude/settings.json`。** 国内几个模型的 endpoint 和
   模型名各不相同，每次改都得翻文档、抄地址、贴 key。
2. **工作区散在硬盘各处。** 每个项目都要 `cd` 过去，记不住路径。

所以它做了两件事：把模型预设存成一个个 json，点一下就覆盖
`~/.claude/settings.json`；把工作区存成一个列表，点一下就在那个目录开窗口
跑 claude。两块互不干扰，启动前随时换模型。

## 数据放在哪

**启动器自己的东西全在 `~/.claude_tool/` 下面**，跟 Claude Code 的配置分开：

| 路径 | 装什么 |
| --- | --- |
| `launcher.json` | 工作区列表、窗口位置、默认工作区目录、底下那三个勾、「AI 托管」上次选的档和工作区 |
| `claude_settings/*.json` | 模型预设，一个模型一个 json |
| `workplace/` | 默认工作区目录，「新建一个文件夹」就在这儿建 |
| `hooks/hook.json` | 挂 Stop hook 用的那份配置，启动时用 `--settings` 临时交给 Claude Code |
| `handoff_state.json` | hook 那两个行为的节流计数，按目录分开记（刷文档的轮数/时刻、自动继续的连计数） |

**唯一的例外是 `~/.claude/settings.json`**——那是 Claude Code 自己的文件，
换模型是往里覆盖一份新内容。除此之外不碰 Claude Code 的任何东西。

这一点直接决定了安装包的行为：**卸载时不能删 `~/.claude_tool/`**，那里面
是用户全部的预设（含 API key）和工作区列表。卸载程序只留一句提示。

## 代码怎么切

```
claude_tool/               包
├─ __main__.py             入口：--hook 走 hook 那条路，否则开窗口
├─ paths.py                所有目录/文件/命名规则常量
├─ theme.py                配色、字体、量文字宽度
├─ permissions.py          权限等级表
├─ config.py               launcher.json 读写、工作区扫描、上次聊时间
├─ presets.py              模型预设 + 常用供应商表
├─ claude.py               找 claude、拼命令行、启动
├─ handoff.py              交接文档的提示词 + Stop hook 本体（挂在这儿的两个行为都在这儿）
├─ winhost.py              ctypes 的窗口操作：内嵌 conhost、独立窗口的认领/挪位/置顶/关闭
├─ widgets.py              自绘控件：胶囊按钮、列表行、滚动区、表单工具
└─ ui/
    ├─ launcher.py         主窗口（最大的一个文件，布局和交互都在里面）
    └─ dialogs.py          那几个对话框
```

行数不写在这份文档里——它每加一个功能就变，写死只会变成一条迟早不对的信息。

### 对话框为什么是 mixin

`dialogs.py` 里的 `LauncherDialogs` 是个 mixin，`class Launcher(LauncherDialogs,
tk.Tk)` 继承它。**方法体一行没改**——它们本来就全是 `self.xxx`，跟主窗口共用
`config_data`、`feedback_var`、`refresh_*` 这些状态。

没做成"把状态收进一个独立的对象再注入"，是因为那要挨个改方法体（每个
`self.config_data` 都得改成 `panel.config_data`），跟"只是把文件切开"是两码事，
风险也不在一个量级。真要那么做，应该连同 `launcher.py` 一起，按面板
（模型面板 / 工作区面板 / 会话面板）重新划分职责，而不是先动对话框。

留在 `launcher.py` 的是**面板自己会调**的那些：`remove_model`、`switch_model`、
`launch_workspace`、`start_autonomy`、`rescan`，还有 `_set_workplace`——它是
「新建一个文件夹」那个对话框建完目录之后要落盘的一步。

依赖是单向的，从下往上：

```
paths / permissions / theme        谁都不依赖
        ↓
      claude  ← handoff / winhost / presets
        ↓
      config        （依赖 paths + permissions）
        ↓
     widgets        （依赖 theme）
        ↓
        ui          （依赖所有）
```

**只有 `ui/` 会 import tkinter。** 这不是洁癖，是硬要求：`--hook`
那条路上不能碰 tkinter，也不能弹任何窗口——那是 Claude Code 在跑对话的
中途回头调的。所以 `__main__.py` 把 hook 分支单独拎出来，连主界面都不 import
（在 `main()` 里面才 import），保证这条路干干净净。

同理，`claude_tool/__init__.py` 是空的。它一旦往里放 import，上面那条
隔离就白做了。

## 会话跑起来之后

对已经跑起来的 claude，启动器**没有输入通道**（Windows 上没法往一个开着的交互式
会话里塞按键），能做的只有窗口层面的操作（挪位、置顶、关掉）和观察。所以下面每一步
都是"拍快照、做差、看文件时间戳"，没有一步是"让它干点什么"。

**新窗口那条路。** 启动前先 `terminal_windows()` 拍一张现有窗口的快照，启动后再拍一张，
差集里就是这次新开的那扇（都在 `winhost.py`）。所以要**先拍后启**——等它冒出来再去数，
就分不清哪扇是这次新开的、哪扇是上一轮留下的。默认终端是 Windows Terminal，新窗口的
类名是 `CASCADIA_HOSTING_WINDOW_CLASS`；按 `ConsoleWindowClass` 找一个都找不到，
两个类名都得认。

**做差有个根本限制。** Windows Terminal 要是被设成"新窗口开成已有窗口的标签页"，
桌面上的窗口数压根不变，做差永远认不出来——那种配置下「移过来 / 置顶 / 关掉」那三个
按钮不会出现。这是限制，不是没修完。

**换模型的时候接着聊。** `switch_model()` 覆盖完 `~/.claude/settings.json` 之后，
`_offer_migration()` 逐个会话弹框问要不要接着聊；答应的话走一条流水线：让旧会话先写
一份交接文档 → 关掉旧窗口 → 用新模型 `--continue` 重开，并带上"先读 handoff.md"的
开场白。**这份交接文档是新模型写的，不是旧模型**——那时候 `settings.json` 已经被覆盖
了，`--continue` 起来的会话读到的就是新预设。主界面顶上那块进度区（走马灯 + 第几个 +
当前步骤 + 已用秒数）就是这条流水线的门面，手动点「整理交接文档」也走同一块。

**时序现在还是写死的毫秒**（等旧窗口退 1500ms、等新会话起来 2500ms）。慢机器上不够，
该改成等条件。这是已知的薄弱处。

**同一份 handoff.md 只许一个写手。** 会话自己的 Stop hook 也可能正在刷这份文档
（见「自主接手」）。撞上时：手动的「整理交接文档」被挡回来并说清后果；换模型的流水线
把那个会话让到队尾，等锁撤了再补一份——hook 那份可能漏掉它停下之前的最后一点新对话。
启动器自己写完之后会顶掉 hook 的节流时间戳，免得两边来回往同一份文件上写。

## 两个必须知道的坑

### hook 命令行指向哪儿

`handoff.py` 里 `hook_command()` 拼的这条命令行给到 Claude Code，让它每次停下来
回头调我们。两种形态，靠 `getattr(sys, "frozen", False)` 分叉：

```
源码：  "python.exe" "…\claude_tool\claude_tool\__main__.py" --hook --handoff --auto-continue
打包后："C:\…\Programs\claude_tool\claude_tool.exe" --hook --handoff --auto-continue
```

`--hook` 是入口标记，后面跟的是**各行为自己的开关**：`--handoff`（自己刷交接文档）
和 `--auto-continue`（停下时接着往下推，见「自主接手」）。这样加第三个行为时不用
再开一条入口路径，`__main__.py` 里也只有一处分支。勾了哪些就写进那一份
`hooks/hook.json`，勾选状态就此固化——改勾不影响已经跑着的会话。
（老版本的入口标记是 `--handoff-hook`，配置在 `hooks/auto_handoff.json`，
启动时顺手删掉那份旧配置。）

源码那条**不能写 `handoff.py` 自己**——那样会被当成脚本直接跑，包内的
`from claude_tool.xxx import` 全部失败。同理 `__main__.py` 里有一段 `sys.path`
引导（冻结时跳过），就是为了让它既能被 `python __main__.py` 直接跑，也能被
`python -m claude_tool` 跑。

路径一律带引号：装到 Program Files 的话里面是有空格的。

### 标准输入输出的编码

**进的那一头。** 这台机器 locale 是 cp936。Python 走管道时 `sys.stdin` 默认按
GBK 解码，而 Claude Code 给的是 UTF-8。只要路径里有中文（工作区叫「冉」
「小说」这种），`json.load(sys.stdin)` 就抛 `UnicodeDecodeError`，被 except
吞掉，表现为"这个功能对中文工作区永远不触发"，且没有任何报错。

所以读的是字节流、自己解 UTF-8（`_stdin_bytes()` + `decode("utf-8", "replace")`）。
**任何新加的、跟外部进程走标准输入输出传数据的地方，都要显式按字节 + UTF-8 处理。**

**出的那一头。** 冻结后这个进程没有控制台，`sys.stdout` 是按系统 locale 开的，
往里写中文就有风险。所以 `json.dumps` 的 `ensure_ascii` 必须保持 True——转义成
纯 ASCII 的 `\uXXXX` 才不挑编码。这不是"默认值无所谓"的事，改成 False 会变成
一个只在中文提示词上才炸的 bug。

**顺带一个反直觉的实测结论。** 这份文档原先写着"`--noconsole` 的 exe 里
`sys.stdin` / `sys.stdout` 是 `None`"。真冻出来撞了一下（PyInstaller
`--noconsole`，管道接在 fd 0/1 上），三个流**都有值**——有句柄 Python 就给赋值，
跟有没有控制台不是一回事。所以 `_ensure_stdio()` 那个兜底不是主路径，留着是防
句柄没传进来的情形：那时 `sys.stdout` 才是 None，而 **print 到 None 是静默无操作**，
block 答复会凭空消失且不报错。这种漏法不值得省那十行。

## 自主接手：别让会话停下来等人

用户发一个目标就离开电脑，是这套东西想做的下一个能力。**麻烦在于开了
`bypassPermissions` 也停不住**：那个档位免掉的只是工具确认，"用 A 方案还是 B 方案"
这类选择 Claude 照样会摆到人面前（`AskUserQuestion` 不受权限等级管，直接用文字
提问同理），所以人还是得坐在那儿。

**能插手的只有一个地方：Stop hook。** Windows 上没法从外部往一个开着的交互式会话
里投喂输入——会话跑起来之后启动器只能观察它。唯一能反过来影响它的，就是 Claude Code
每轮把控制权交还给用户之前跑的那一次 Stop hook：回一句
`{"decision":"block","reason":"…"}` 就能逼它再干一轮。自动刷交接文档和自动继续架的
是同一个杠杆，所以共用一个入口。

### 入口：主窗口那个「AI 托管」按钮

按"接手到什么程度"分档，往上加档，用户自己选。

入口是「工作区」标题底下那一行的 **「AI 托管」**按钮——摆在那儿而不是顶栏，是因为
托管要挑的就是一个工作区，跟"在哪儿挑工作区"本来就是同一件事。按下去弹一个对话框：
挑工作区（默认上次托管的那个）、写一段任务目标、选一档。点「开始托管」= 在那个
工作区起一个**新**会话（不带 `--continue`），任务目标当命令行上的位置参数送进去当
第一条用户消息，然后按那档挂 hook。两件事都撞过：`claude "任务"` 不带 `--continue`
时开场白确实成了会话记录里的第一条用户消息（2026-09-19 用一个临时探针实测）。

档位和上次用的工作区记在 `launcher.json` 的 `autonomy` / `autonomy_workspace` 里，
下次打开对话框直接停在原处；写坏的档位（4、字符串）一律回落第 1 档。

对话框里**摆着这个工作区的权限等级并附一句警告**，因为"它问你话"和"它等你点允许"
是两种不同的停顿：**Stop hook 只接得住前一种**。权限不够高时用户走开一趟，回来会
发现它卡在权限确认上——那不是托管失灵，是权限的事。这句话是为了别让人误会。

底下那排的**「自动继续」勾还在**，管的是"平时随手开一个会话要不要自动继续"，
跟托管对话框里当场选的那一档互不影响。托管那次会话把两者**取并集**：底下勾着
「自动刷交接文档」的话，托管会话两个 hook 都挂；只勾托管，就只挂自动继续。

| 档 | 干什么 | 状态 |
| --- | --- | --- |
| 1. 让它自己定 | 它停下来等你的话，一律回一句「接着干，自己定」 | 已落地一半（`--auto-continue` 管的是 `Stop` 那种停；它用 `AskUserQuestion` 摆选项问你那半还没做） |
| 2. 接指挥模型 | 让一个小模型读交接文档 + 最后一条助手消息，答它真正问的那个问题 | 没做，对话框里灰着 |
| 3. 半指挥 | 平时让它自己跑，碰上改 git 历史、大范围重做这种，停下来等你 | 没做，对话框里灰着 |

**第 1 档原来还分过一个「替它选」**（`PreToolUse` 拦下 `AskUserQuestion`、把选项答案喂
回去）。后来合并掉了：那条路没人来选的时候，兜底还是回它一句"你自己定"，跟第 1 档
一个效果——两个档摆着一个样的东西，不如并成一个。合并之后第 1 档要管两种停：
`Stop`（已经做了）和 `AskUserQuestion`（还没做）。

第 1 档**故意不接第二个模型**，就回一句固定的话：先量出这条路到底能吃下多少停顿，
再决定值不值得上一个指挥模型。零成本，坏了也坏不到哪儿去。

第 2、3 档**列出来但灰着**。列出来是因为用户得看得见这条路往上还有什么；灰着是
因为点下去就得装作托管着——宁可让他知道还没做。

第 3 档跟第 1、2 档是**反方向**的：前两档是"别回来烦我"，第 3 档是"平时别回来烦我，
但这几件事必须先问我"。要划的那条线（现在想到的）：改 git 历史（`rebase` / `reset
--hard` / `push --force` / 改已提交的历史）、大范围重做（几十个文件一起动、推倒重来
的那种）、删东西。**判据还没定**——是让模型自己按提示词判断、还是 `PreToolUse` 拦
具体命令，两条路都还没撞过。

### 第 1 档的护栏

- **连着续 `AUTO_CONTINUE_MAX`（8）次就放行。** 平台自己对连着拦的次数也有限制，
  取 8 是照文档里那句"一次停顿大约连着拦 8 轮会被强制收尾"来的（这个数没实测过，
  反正比它小就安全）。
- **距上次续超过 `AUTO_CONTINUE_RESET`（10 分钟）就把连计数清零。** 中间隔了十分钟，
  要么是用户回来敲过字、要么是模型自己在干长活，两种情况都该重新开始帮它往前推。
  这也顺带兜住了总量——不在那儿清的话，一个卡住的会话会被无限期地催下去。
- **它自己说「已完成」就停。** 模型说这句就是收工了，别再去催一个做完的会话往下编。
- **`stop_hook_active` 这条故意不认。** 那个标记只有"被 hook 逼出来的那一轮"才带；
  自动继续要是认了它，一次对话最多只能续一轮，等于没这个功能。护栏改由上面那个
  连计数自己数。（刷交接文档那条反过来，**必须认**——认了才不会来回往同一份文件上写。）

### 后面几档要接的东西（先记着，真做的时候逐条复核）

**第 1 档剩下那半（`AskUserQuestion`）：**

- **它和 `Stop` 不是一回事**：`AskUserQuestion` 不走权限确认（`bypassPermissions` 也
  拦不住它）、`Stop` 不为它触发。所以那半得挂在 `PreToolUse` 上，由 `__main__.py` 那个
  唯一的 hook 入口按 `hook_event_name` 分发（加行为别另开入口，这条已经在遵守了）。
- **回什么让它"自己定"还没撞过**。回 `allow` + `updatedInput`（带 `answers`）是"替它选
  好答案"，等于要把答案编出来——那正是被合并掉的那条老路。想让第 1 档保持"不编答案"，
  大概得回 `deny` + 一句「用户不在，按你自己的判断定」，让被挡掉的工具调用连理由一起
  当成指令读。**这只是猜的**（现在文档里"回 deny 会让它重新问一遍"那句也是猜的），
  真做的时候先拿一个探针把 `deny` / `allow+updatedInput` 各自的行为撞清楚。
- **别弄成死循环**：万一 `deny` 之后它又摆一次选项，就得跟 `--auto-continue` 一样有个
  连计数兜底，连着挡几次就放行。

**第 2 档（接指挥模型）：**

- **指挥模型从哪来**：这台机器的 `~/.claude/settings.json` 里 `ANTHROPIC_BASE_URL`
  指着别的供应商，`--model haiku` 这类内置名字会一起被路由过去——所以指挥模型得从
  用户自己的预设文件里挑。调用形如 `claude -p --settings <那份预设>`。
- **它只答，不做**：「谁来答它的问题」和「谁允许它动手」是两个旋钮，各管各的。指挥
  模型答完之后，真正执行仍然按那个会话自己的权限等级走。
- **答不出来就放行**：指挥模型超时、报错、答非所问，一律 fail open——照常停下来问
  用户。不能因为一个答不上来的副手把用户的目标卡死在半路。

**第 3 档（半指挥）：**

- **判据放哪儿**有两套走法，都还没撞过：写进 hook 回的那句 reason 里（让模型自己按提示
  词判断"这算不算大改动"，省事但靠自觉），或者挂 `PreToolUse` 拦具体命令（认得出
  `git reset --hard`，但认不出"这次重做主界面"这种语义上的大动作）。真做的时候大概
  得两条一起上。
- **"呼叫用户"本身没有现成办法**：Windows 上没法往一个开着的会话里投喂输入（见上面
  「会话跑起来之后」），能做的只有"停下别推它"——也就是这一档**不挂自动继续**，让它
  照常停在提示符上等。想要真有声响，得另外想办法（托盘气泡、响一声之类），那是另一件
  事，现在没打算做。

## 怎么跑

```bat
运行.bat
```

等价于 `python claude_tool\__main__.py`。这条路上看得见报错，开发时用。
打包出来之后，给用户的是开始菜单里的快捷方式，不依赖机器上有没有 Python；
`dist\claude_tool\` 整个目录拷走也能直接双击跑，那份是免安装的。

单独试 hook（`cwd` 指到哪儿，节流就算在哪份记录上）：

```bat
echo {"cwd":"D:\\某目录"} | python claude_tool\__main__.py --hook --handoff
echo {"cwd":"D:\\某目录"} | python claude_tool\__main__.py --hook --auto-continue
```

什么都不打印 = 放行；`{"decision":"block","reason":…}` = 把 claude 拦下来再干一轮。
`_probe_autocontinue.py` 就是这么撞的——纯子进程，不需要开窗口，跑起来最快。

## 怎么打包

```bat
build\打包.bat
```

一条龙：PyInstaller 出 `dist\claude_tool\`，Inno 再打成
`Output\ClaudeLauncher-<版本>-Setup.exe`。构建期要有 PyInstaller 和 Pillow（后者
是 PyInstaller 往 exe 里嵌图标用的），跟打包出来的程序无关——那个仍旧零第三方依赖。

```
build/
├─ claude_tool.spec   PyInstaller：onedir + 无控制台，入口是 claude_tool/__main__.py
├─ claude_tool.iss    Inno：安装包
├─ 打包.bat           上面两个依次跑一遍
├─ icon.png           图标源图
├─ make_icon.py       PNG → 多尺寸 ico，换图时才跑
└─ icon.ico           生成物，提交进仓库（平时打包不必重跑 make_icon）
```

几个决定，改之前先看：

- **onedir 不 onefile。** 启动快（不用每次解包到临时目录），杀软误报也少。
  反正 Inno 装的就是一整个目录，分发形态没差别。
- **exe 名和安装目录用 ASCII**（`claude_tool.exe`、`{autopf}\claude_tool`），
  中文只出现在显示名、快捷方式和开始菜单上。hook 命令行里要塞安装路径，
  全程 ASCII 能少一整类编码麻烦。
- **装的时候让用户自己选**（`PrivilegesRequiredOverridesAllowed=commandline dialog`）：
  默认免管理员装到 `%LOCALAPPDATA%\Programs`，想整机共用可以走 `/ALLUSERS`
  或在界面上切，`{autopf}` 会跟着变。
- **`AppId` 那个 GUID 定下来就别改**，升级安装靠它认出是同一个软件；改了会变成
  新旧并存两份，而不是覆盖升级。
- **`[Code]` 段里 `;` 不是注释符**，Pascal 只认 `//`。写成 `;` 会报
  `'BEGIN' expected`，而且报错行号指在注释上，看着莫名其妙。
- **`.iss` 必须带 UTF-8 BOM**，否则 Inno 按系统 ANSI（这台机器即 cp936）读，
  里面的中文全乱。
- 卸载**不碰** `~/.claude_tool/`：Inno 默认就不会去删没装过的路径，我们只额外留
  一句提示告诉用户数据还在。那句提示包了 `UninstallSilent` 判断——脚本自己弹的
  MsgBox 不受 `/SILENT` / `/SUPPRESSMSGBOXES` 管，不判断的话静默卸载会卡在一个
  没人看的框上。

## 还差什么

- **面向使用者的安装说明**（`docs/使用说明.md`）：装完之后给人看的那份，
  连"SmartScreen 拦一下要点仍要运行"都得写进去。
- **代码签名**：没签名的话下载下来会被 SmartScreen 拦。真要转发给外人，
  这一步影响观感最大。
- **只有 64 位**（`ArchitecturesAllowed=x64compatible`），32 位 Windows 装不上。

## 搬运式重构怎么保证没改坏

拆模块和拆对话框都是纯搬运，但"搬运时少抄一行 import"这类错误，在运行到
那条分支之前不会暴露。这两次用的三道检查，以后大改结构可以照做：

1. **定义集合与源码文本比对。** 用 `ast` 取出重构前的每个函数，跟重构后的
   逐字比。结果应该是"除了有意改的那几处，其余全等"。
   注意**别把类整体算进去**——`Launcher` 换了基类、去掉一半方法，类那段文本
   本来就该变，算进来只会报一条没意义的"文本变了"。
2. **漏 import 扫描。** 反汇编每个模块，把所有 `LOAD_GLOBAL` 的名字揪出来，
   既不在本模块 globals 里、又不是内置的，就是漏了 import。注意要按
   `__module__` 过滤，否则一路 import 进来的函数会按本模块的 globals 去量，
   满屏假报错。
3. **多余 import 扫描。** 反过来说，搬走之后原模块会剩下一堆没用的 import。
   数一下每个 import 进来的名字在文件里出现的次数，只出现一次（就是 import
   那一行）的列出来手工核。这个只能当提示，字符串和注释会造成误判。

外加 A/B 截图：同一套沙箱配置下，重构前后各跑一遍，截屏逐像素比。主窗口和
"加模型"对话框都这么比过。两个坑：
- **要排除窗口阴影那一圈**——它是 DWM 拿桌面背景混合出来的，跟代码无关，
  不排除的话满屏都是 1-2 个像素的假差异。
- **沙箱路径要写死**，别用 `mkdtemp`：临时目录名每次都变，界面上那行路径
  跟着变，逐像素比时全是噪声。

还有一件容易漏的：界面上跑不到的分支（错误提示、异常处理）三道检查都盖不住
——它们只保证"搬运没错"，不保证"逻辑对"。真遇到这类分支，单独写探针去撞它。

## 打包那步怎么验

跟重构一个道理：跑不到的地方就不知道对不对。打包验这几样：

- **冻出来的 hook 单独撞一遍。** `echo '{"cwd":"…"}' | dist\claude_tool\claude_tool.exe
  --hook --handoff`，连打几次看节流（前两次放行、第三次拦、第四次重新计数）和
  中文路径；`--hook --auto-continue` 再撞一遍连计数和上限。这是整条链上最容易碎的
  一环，必须单独测，不能靠"主界面能开"推断。
- **A/B 截图验冻结版。** 源码版和冻结版各截一张逐像素比，用来确认 PyInstaller
  没漏掉 tcl/tk、字体或插件。仓库根下的本地脚本 `_probe_ab_shot.py` 干这个
  （被 .gitignore 收着，不进仓库）：它把沙箱 `USERPROFILE` 指到一个写死的路径、
  跑前清干净、按窗口标题找 HWND 挪到固定位置再截。

  **"冻结版命令行到底长什么样"这件事没做端到端验证**——那要真拉一次 claude 会话。
  验的是两头：探针在真冻结进程里读到 `frozen=True`、`sys.executable` 就是 exe 路径，
  而 `hook_command()` 的分叉是单独用假 `frozen` 撞过的。拼起来是确定的，但确实
  没有一次"从界面点出去、读回写下的那行命令"的实跑。要补的话在这里补。

- **装一遍再卸一遍，量三样东西。** 卸载**不能只看安装目录空没空**：
  - 安装目录整棵没了、桌面和开始菜单快捷方式没了、注册表 `Uninstall` 项没了；
  - `~/.claude_tool/` 的文件数**和 `launcher.json` 的 md5** 跟装之前一致
    ——"卸载不删用户数据"是承诺，得量出来，不能凭"Inno 默认不删"推断；
  - 卸载日志里 `Removed all? Yes`。

- **一个踩过的坑：git-bash 会改写 `/` 开头的参数。** `./Setup.exe /VERYSILENT`
  到 Inno 手里变成了 `"C:/Program Files/Git/VERYSILENT"`，静默安装根本没生效，
  于是 `[Run] postinstall` 把程序真拉起来了——程序文件被运行中的自己占着，
  卸载删不掉，日志里报 `Failed to delete the file; it may be in use (5)`。
  这个错看着像"卸载器有 bug"，其实是测试命令错了。传参数用 PowerShell 的
  `Start-Process -ArgumentList ... -Wait`（顺带能拿到真实退出码），或者设
  `MSYS2_ARG_CONV_EXCL='*'`。
